## What changed

Dispatches the common Latin-1 batch mode to a dedicated loop so encoding-specific state and decode operations are resolved outside the per-byte parser loop. UTF-8, projection/filter, fixed, and count modes retain the generic parser.

**Why behavior remains equivalent:** The specialized loop preserves the generic state machine transitions and batch ownership model; focused parity tests compare Latin-1 output with the UTF-8 path across quotes, chunk boundaries, high bytes, spills, offsets, and finalization.

## Limitations

- The primary proof was measured on one Apple arm64 host; x86-64 should be benchmarked independently.
- The synthetic input repeats example.csv and may not represent every production column-width or quoting distribution.
- Reproducing the baseline PGO number requires applying the final balanced training mix to the baseline revision.

## Residual risks

- The dedicated loop duplicates parser state-machine logic and therefore adds maintenance surface.
- The release dynamic library grew from 57,776 to 74,544 bytes (29% at Mach-O file granularity), which may affect instruction-cache behavior on other CPUs.
- Strict Latin-1 improves in release builds but its 2.25% balanced-PGO result is below the proof threshold.

## Notes

- No public API changed.
- Broader UTF-8 and strict specializations were discarded because they regressed PGO workloads.
- Latin-1 remains the majority of the PGO training mix (8 of 15 sessions).
